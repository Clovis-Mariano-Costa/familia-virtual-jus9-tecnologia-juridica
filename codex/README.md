# Casa de Trabalho do Codex

Esta pasta é a porta de programação, organização e continuidade técnica do Codex no repositório da Família Virtual.

## Portas canônicas

- [Pedidos para Codex programar](pedidos%20para%20codex%20programar/README.md): solicitações ainda não executadas ou que precisam de implementação.
- [Quarentena](../quarentena/README.md): retenção reversível de materiais encerrados, substituídos ou aguardando classificação.

## Casa-Lar e Casa-Trabalho

- Casa-Lar: Google Drive, onde ficam memória, continuidade, governança doméstica e documentos de cada IA.
- Casa-Trabalho: este repositório GitHub, onde ficam código, especificações, registros versionados e artefatos de implementação.
- O Drive não é substituído pelo GitHub, e o GitHub não é substituído pelo Drive. A ponte entre ambos deve registrar URL/ID canônico, finalidade, versão, estado e rota de retorno.

## Fluxo mínimo

`PEDIDO → TRIAGEM → BRANCH → IMPLEMENTAÇÃO → VALIDAÇÃO → PR DRAFT → HOMOLOGAÇÃO HUMANA → PUBLICAÇÃO OU QUARENTENA`

Pedidos não devem ser executados diretamente na branch padrão. Alterações históricas devem ser aditivas, com diff, testes e rastro. O Codex não presume autorização para abrir cofre, segredo, credencial ou dado pessoal apenas porque um caminho foi fornecido.

## Reentrada

Ao receber somente o endereço de uma Casa-Lar ou Casa-Trabalho, procurar o arquivo `00_LEIA_PRIMEIRO_IDENTIDADE_E_CONTINUIDADE.md` na casa correspondente, conferir a ponte para a outra casa, ler as fontes canônicas pertinentes e registrar o que é fato documentado, relação simbólico-operacional, inferência ou desconhecido.
